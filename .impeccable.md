# Smart Shopper — Design Context

## Design Context

### Users
Home cooks who treat cooking as craft, not chore. They plan meals, draft and refine recipes, and shop through Kroger. They use the app at the kitchen counter on a laptop or tablet — sometimes following a recipe mid-cook, sometimes editing one before saving. They want to read the recipe like a recipe, and edit it like a notebook — but not both at once.

### Brand Personality
**Warm. Considered. Confident.** A knowledgeable friend who cooks — never pretentious, never sterile. The product celebrates food and its stories. Closer to a thoughtful cookbook than a SaaS dashboard. Three words: *culinary, unhurried, opinionated.*

### Aesthetic Direction
Clean editorial — the feel of a printed recipe in a well-designed cookbook. Generous whitespace. Restrained color (warm cream surfaces, sage and terracotta accents already established in the OKLCH token system). Display serif for titles, refined sans for body and UI chrome. Information density only when the user opts in (edit mode).

Theme: **light**. Cooking happens in daylight kitchens; the warm cream/OKLCH palette already reflects this.

Anti-references: dashboard SaaS, dense admin tables, "AI-assistant" gradient sheen, generic icon-and-card grids.

### Design Principles
1. **Reading first, editing second.** Default state is a clean recipe page. Edit affordances are summoned, not standing.
2. **Information on demand.** Health, pantry, source, and safety signals live as compact indicators in view mode and expand on hover/click. They become explicit fields only in edit mode.
3. **Warm and quiet.** Use the existing OKLCH cream/sage/terracotta palette. No high-chroma accents. No gradient anywhere. No glowing dark-mode UI.
4. **Typography carries the hierarchy.** A distinctive display serif (Lora-equivalent for titles) and a calm humanist sans (DM Sans is in-use; replacement candidates welcome) — but rely on weight and size for hierarchy, not boxes and borders.
5. **One toggle, not a thousand controls.** A single Edit/Done state change reveals everything editable. No second toggle, no third mode.
